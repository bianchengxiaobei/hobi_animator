## 6. 回归与 CI

- `ctest` 跑全部测试（主构建 195，EnTT 196）；任何超差即失败。
- `ctest` 不依赖 Unity 2019；Unity 4.7 离线 fixtures + 功能测试是默认门槛，Unity 2019 oracle 仅用于可选精确模式。
- 每次修改**曲线求值 / 肌肉公式 / 混合算法**后必须全量重跑。
- 生成的黄金数据提交进仓库；体积大时用 LFS 或生成脚本（记录源 `.anim` 与提取规则）。

## 7. Unity 侧采样注意事项（可选精确模式）

> 以下步骤只在有 Unity 2019.4 环境且需要数值对齐时执行；没有环境时跳过，不影响 `ctest` 和功能验收。

- **必须使用与 C++ 相同的骨架与 T-Pose**（否则骨骼比较无意义）。
- 编辑器采样（`AnimationMode`）与运行时采样可能有差异；统一选一种并在文档记录。
- 人形肌肉值受 Avatar `humanScale` 影响，导出时记录该值。
- 记录 `Animator.bodyPosition/bodyRotation`（人形根）以便验证根空间。
- 单肌肉标定使用 `HumanPoseHandler.SetHumanPose`，每次只设置一个 muscle，
  避免多轴顺序/混合污染样本。

### 7.1 可选精确模式：生成并反解人形标定数据

1. 在 Unity 2019.4 打开本工程，执行菜单
   `Tools/AnimancerCpp/Dump Humanoid Muscle Golden`。
2. 脚本会生成 `AnimancerCpp/golden/HumanoidGolden.json`。
3. 在 C++ 构建目录执行：

```bash
anim_calibrate --golden ../golden/HumanoidGolden.json \
               --out ../golden/DefaultHumanoid.avatar.json --tolerance 0.1
```

4. `anim_calibrate` 输出 `preRot/postRot/limitsOverride`；测试失败时会打印
   残余角度最大的 muscle，便于定位轴序或 Avatar 不匹配。
5. 全身数据：执行菜单 `Tools/AnimancerCpp/Dump Humanoid FullBody Golden`，
   使用 `AnimationClip.SampleAnimation`（与 `AnimancerUtilities.EditModeSampleAnimation`
   相同的编辑器采样路径）生成 `AnimancerCpp/golden/HumanoidFullBodyGolden.json`。
   每个 sample 记录所有 human bone 的 local rotation；下一步用 `avatar.json`
   的 `preRot/postRot/limitsOverride` 应用后逐帧对拍。

### 7.2 离线回归路线（默认）

不需要伪装成 Unity oracle：本机 `E:\Learn\Unity4.7` 的 Mecanim 源码包含
`HumanSetupAxes`、`skeleton::SetupAxes`、`ZYRoll2Quat`。用
`tools/unity_humanoid_axes.py` 直接解析 `.fbx.meta` 的 human/skeleton 数据：

```powershell
py -3 tools/unity_humanoid_axes.py `
  --meta "../Assets/.../DefaultHumanoid.fbx.meta" `
  --unity-source E:/Learn/Unity4.7 `
  --out tests/golden/DefaultHumanoid.source.avatar.json `
  --skeleton-out tests/golden/DefaultHumanoid.skeleton.json
```

产物包含 Unity 的 `uvw/preRot/postRot/limitsOverride`，不是旧
`dqX*dqY*dqZ` 近似；`AvatarLoader`/`AvatarBuilder` 直接加载。当前仓库已提交
`tests/golden/DefaultHumanoid.*` 作为回归夹具。

再用 `Human2SkeletonPose` 公式生成 Walk/Run/Idle 的全身参考：

```powershell
py -3 tools/unity_humanoid_fullbody.py `
  --avatar tests/golden/DefaultHumanoid.source.avatar.json `
  --skeleton tests/golden/DefaultHumanoid.skeleton.json `
  --anim "../Assets/.../Humanoid Animations/Humanoid-Walk.anim" `
  --out tests/golden/DefaultHumanoid.walk.fullbody.json
# Run 用 --times "0,0.1875,0.375,0.5625,0.75"
# Idle 用 --times "0,1.84375,3.6875,5.53125,7.375"
```

该脚本独立解析曲线并处理 `m_PreInfinity/m_PostInfinity`，计算
`rest * pre * ZYRoll(uvw) * post`，并把 `RootT/RootQ` 作为 Hips 的完整
local TRS、把四个 goal T/Q 按 `GetHumanPose` 原样输出，不会调用 C++
运行时。对应测试覆盖 3 个 clip、各 5 个时间点、54 根 human bone、
Hips 根变换和四个 goal。当前回归覆盖 human bone local rotation、Hips
根 TRS 与 goal 数据。完整 `FullBodySolve` IK 求解属于可选精确模式，不作为当前
离线回归要求；真实 Unity 2019 oracle 同样为可选精确模式，不阻塞当前 CI。

> 注意：`anim_calibrate` 的输入仍是单轴样本，输出的 `pre/post` 只适合旧
> 兼容公式。要做 Unity 多轴对拍，应使用本节的离线轴表；Unity Editor
> full-body 数据属于可选精确模式。
