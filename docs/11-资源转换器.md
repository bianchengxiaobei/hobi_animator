# 11 · 资源转换器（`.anim` → `.ab`）

离线工具 `tools/anim_converter`：把 Unity `.anim`（YAML）转换为本库的高效二进制 `.ab`，并配合 `*.avatar` 配置完成骨骼/肌肉绑定。**运行时不解析 YAML。** 另有可选的 `tools/anim_pack`（Blender/glTF → `.ab`），见 §13。

## 1. 输入 / 输出

| 输入 | 作用 |
|------|------|
| `*.anim` | Unity 动画曲线（骨骼本地 或 人形肌肉） |
| `*.fbx.meta`（可选） | 提取 `boneName → humanName` 映射，辅助生成 `*.avatar` |
| `*.avatar`（本库配置） | HumanBone→你的骨架骨名、T-Pose、limits、hipsHeight |
| 你的模型骨架资产 | 提供 bone 名、层级、rest pose（由引擎模型导入器提供，转换器只读其导出的清单） |

| 输出 | 内容 |
|------|------|
| `*.ab` | 见 [03 §4](03-动画数据与曲线.md) 的二进制布局 |

## 2. `.anim` 结构（实测）

`Examples/Art/Humanoid Animations/Humanoid-Walk.anim`：
- `AnimationClip.m_FloatCurves[]`：每条含 `curve`（`m_Curve[]` 关键帧 + `m_PreInfinity/m_PostInfinity`）、`attribute`、`path`、`classID`。
- 人形：`attribute` ∈ {`RootT.x`, `Spine Front-Back`, `LeftFootQ.w`, `LeftHand.Thumb.1 Stretched`, ...}，`path` 为空。
- 通用：`attribute` ∈ {`m_LocalPosition.x`, `m_LocalRotation.w`, `m_LocalScale.y`}，`path` 为骨路径（如 `Root/RightUpperLeg`）。
- 另有 `m_RotationCurves/m_CompressedRotationCurves/m_EulerCurves/m_PositionCurves/m_ScaleCurves`（本样本为空，仍需支持）。

关键帧字段：`time, value, inSlope, outSlope, tangentMode, weightedMode, inWeight, outWeight`（见 [03 §1](03-动画数据与曲线.md)）。

## 3. 解析策略

> Unity YAML 含自定义标签（`%TAG !u! tag:unity3d.com,2011:`、`--- !u!74 &7400000`）。通用 YAML 库（yaml-cpp）默认会因未知 tag 报错。

两种方案，**推荐 B**：
- A. 用 yaml-cpp + 注册未知 tag 处理（可行但脆弱，大文件慢）。
- B. **定向解析器**：只识别 `AnimationClip` 文档，按缩进/键名扫描 `m_*Curves` 与关键帧列表。实现简单、健壮、快。本库采用 B，并为 `m_Curve` 写专门的流式解析。

伪流程：
```
parse(file):
  skip header (%YAML, %TAG)
  expect '--- !u!74 &...'  // AnimationClip
  parse top map: m_Name, m_Legacy, m_Compressed, m_*Curves[]
  for each curve block:
     read 'attribute', 'path', 'classID'
     read m_Curve[] keyframes
  build Curve objects
```

## 4. 分类与绑定

判定：
- 若 `attribute` 以 `RootT/RootQ/` 或属于 `MuscleTable` 的名称 → **HumanoidClip**。
- 否则若 `attribute` 为 `m_LocalPosition/Rotation/Scale.*`（带 `path`）→ **BoneLocalClip**。
- 其它 `m_FloatCurves`（非骨骼/未知 attribute，含 classID 非 95）→ **属性通道**
  `PropertyChannel{path, attribute, curve}`（见 [10 §8](10-根运动与Animation-Jobs.md)）。
  Humanoid 与 BoneLocal Clip 都可携带属性通道；空 path 存 `0`。

### 4.1 BoneLocalClip：path → boneIndex

转换器读取 `*.avatar` 中的“骨路径/骨名表”（由模型导入器导出），把 `.anim` 的 `path` 映射为 `boneIndex`。
- 支持路径式（`Root/Spine/Chest`）与名字式匹配；缺省骨保持 rest。
- 若某 path 找不到，记录警告并跳过该通道（不中断）。

### 4.2 HumanoidClip：attribute → MuscleId

用 [05 §2](05-人形肌肉空间与重定向.md) 的 `MuscleTable`（`MuscleTable.h` 的静态表）把名称映射到 `MuscleId`。
- `RootT/RootQ` 与手脚 T/Q 单独存。
- 手指肌肉按需保留。
- 未知 attribute → 警告并跳过。

## 5. 曲线转换

- 逐关键帧拷贝 `time/value/inSlope/outSlope/inWeight/outWeight/tangentMode/weightedMode`。
- 排序校验：时间必须严格升序；重复时间合并（保留后者）并警告。
- 保证首/尾外插语义（`m_PreInfinity/m_PostInfinity`）映射到 Curve 的外插策略。

## 6. `*.avatar` 配置格式（自定义，文本）

建议用简洁的文本或 JSON（转换器与运行时共用）。示例：
```json
{
  "name": "DefaultHumanoid",
  "hipsHeight": 1.0,
  "bones": {
     "Hips": "mixamorig:Hips",
     "LeftUpperLeg": "mixamorig:LeftUpLeg",
     "...": "..."
  },
  "restPose": { "source": "skeleton" },           // 用骨架资产的 rest pose
  "preRot":  { "Spine": [0, 0.7071068, 0, 0.7071068] },
  "postRot": { "Spine": [0, -0.7071068, 0, 0.7071068] },
  "uvw": {
    "Spine": [null, null,
      {"muscle":"Spine Front-Back","sign":1,"min":-40,"max":40}]
  },
  "limitsOverride": { "Left Lower Leg Stretch": [-30, 90] }
}
```
- 可从 `.fbx.meta` 的 `boneName→humanName` 自动生成初稿，再人工校对。
- `restPose` 直接取自引擎骨架的绑定姿态（T-Pose 必须正确，否则重定向失真）。
- `preRot/postRot` 可由 `anim_calibrate` 或 `tools/unity_humanoid_axes.py` 生成，
  键为 `HumanBone` 规范名，值为 Unity 顺序 `[x,y,z,w]`。
- `uvw` 是 Unity 的 `(DoF[2],DoF[1],DoF[0])` 三槽绑定，槽位使用
  `ZYRoll2Quat`；`AvatarBuilder` 会把它和 `pre/post/limits` 一起应用到
  `HumanoidAvatar`。没有 `uvw` 的旧 avatar 仍走 `dqX*dqY*dqZ` 兼容路径。

## 7. CLI

```
anim_converter --input Walk.anim --avatar DefaultHumanoid.avatar \
               --skeleton skeleton.json --output Walk.ab
anim_converter --batch clips/ --avatar ... --out-dir out/
anim_converter --fbx-meta DefaultHumanoid.fbx.meta --emit-avatar DefaultHumanoid.avatar

# P4.1：Unity HumanPoseHandler 黄金数据 → 带 preRot/postRot/limits 的 avatar.json
anim_calibrate --golden golden/HumanoidGolden.json --out DefaultHumanoid.avatar.json

# 无 Unity Editor：从 .fbx.meta + Unity 4.7 源码生成 uvw/pre/post/limits
py -3 tools/unity_humanoid_axes.py --meta DefaultHumanoid.fbx.meta \
      --unity-source E:/Learn/Unity4.7 --out DefaultHumanoid.avatar.json \
      --skeleton-out DefaultHumanoid.skeleton.json
```

返回码：0 成功；非 0 表示解析/绑定错误（打印明细）。

> `anim_calibrate` 输出没有 Unity 的 `uvw`/`sign`，只能走旧
> `dqX*dqY*dqZ` 路径；要做 Unity 多轴等价对拍，请使用
> `tools/unity_humanoid_axes.py` 生成带 `uvw` 的 avatar。

## 8. 校验（转换器自测）

1. **读回自检**：`.ab` 读出后，在若干 `t` 采样，与“直接从 YAML 解析的曲线值”比较，误差 `<1e-5`。
2. **通道计数**：Humanoid 应得到预期数量的肌肉曲线（核心约 95，缺手指则更少）。
3. **端到端**：`.ab` 进入 C++ 播放后，与 Unity 黄金数据一致（见 13）。

## 9. 边界情况

| 情况 | 处理 |
|------|------|
| `m_Legacy: 1`（旧式动画） | 警告并拒绝（对齐原 `Validate.AssertNotLegacy`） |
| `m_Compressed: 1` | 明确拒绝并提示（`compressed AnimationClip is not supported`）；不静默跳过 |
| `m_EulerCurves` 非空 | 转四元数后写入 rotation 通道 |
| 空 Clip / 全静态 | 允许；Length=0 时按原项目“零长度”语义处理（End 每帧触发） |
| 缺失 Root | 根运动为无；Hips 作为根 |

## 11. 与原项目对照

原项目不转换资源（直接读 Unity `AnimationClip`）。本库的 `.anim` 字段语义必须与 Unity 的 `AnimationCurve`/`AnimationClip` 完全一致（见 03），否则逐帧会漂移。转换器是“忠实搬运 + 绑定”，不做任何曲线平滑/重采样，以保证可对拍。

### 12.2 `skeleton.json`（本库约定）

```json
{
  "bones": [
    {"name":"Root","parent":-1,
     "translation":[0,0,0],"rotation":[0,0,0,1],"scale":[1,1,1]},
    {"name":"Spine","parent":0,"translation":[0,1,0]}
  ]
}
```

- `rotation` 为 `(x,y,z,w)`；可省略（默认 identity）。
- `parent` 必须先于 child（拓扑序）；`bones` 数组顺序就是运行时 `boneIndex`。
- `inverseBind` 可选，列主序 4×4、16 个数；存在时优先使用。缺失时加载器按
  当前 rest pose 计算 `inverse(world)`，用于兼容旧的 `skeleton.json`。
- **Generic 转换必须显式传入 `--skeleton`**（真实骨架）。
- 未提供 `--skeleton` 时，仅作为兼容 fallback 按 `.anim` 的 `path` 自动生成
  最小骨架（Root + 路径层级）并打印 warning；该 fallback 不应用于正式资源。

### 12.3 行为细节

- `m_Legacy: 1` / `m_Compressed: 1`：报错拒绝。
- `m_LoopTime` → `Clip::looping`；`length = m_StopTime - m_StartTime`。
- `m_PreInfinity/m_PostInfinity` → `Curve::preWrap/postWrap`。
- `tangentMode`：`constant = (tangentMode & 0x3) == 3`（示例数据无常量段；
  Unity 黄金数据校准属于可选精确模式，当前用手工 constant 数据回归）。
- `m_EulerCurves` 按 ZXY 转四元数，并在所有关键帧时间并集上重采样
  （切线 = 中心差分），会打印 warning。
- 事件 `time` 转为 `(time - startTime) / length`，名称存 `hashString`。
- `*.avatar` 目前用于**校验骨名**；limits/hipsHeight 不写入 `.ab`，
  运行时仍由 `HumanoidAvatar` 提供。

### 12.4 验证

## 13. Blender / glTF：`anim_pack` + 事件 sidecar（P8.2-P8.6）

`tools/anim_pack` 是独立离线工具，使用 cgltf 1.14（MIT，`tools/anim_pack/third_party/`），
不进入运行时核心库，也不被默认构建编译。命令：

```powershell
cmake -S . -B build_pack -DANIM_BUILD_ANIM_PACK=ON
cmake --build build_pack --config Release --target anim_pack anim_pack_demo
build_pack/tools/anim_pack/Release/anim_pack.exe `
  --input character.glb `
  --out-dir build/anim `
  --manifest clips.json `
  [--skeleton-out character.skeleton.json] `
  [--coordinate gltf|mirrored] `
  [--strip-action-prefix Armature|] `
  [--events events.json]
```

输入输出：

- 输入 `.glb` 或 `.gltf`（支持 data URI 和外部 buffer），读取第一个 skin；
- 输出 `<out-dir>/<input-stem>.skeleton.json`、每个 Clip 的 `.ab`、输出目录下的 manifest；
- manifest 的 `file` 相对 `--out-dir`；骨架路径相对输出 manifest；
- cgltf 解析、joint 拓扑排序、非 joint 父链合并（rest local 与动画 T/R/S 切线）、
  inverseBind 读取/缺失回退均在工具内完成；
- `.ab` 由 `anim::encodeClip` 写出，并在打包后立即 `decodeClip` 校验。

仓库内可直接执行的合成夹具命令：

```powershell
cmake -S . -B build_pack -DANIM_BUILD_ANIM_PACK=ON
cmake --build build_pack --config Release --target anim_pack anim_pack_demo
build_pack/tools/anim_pack/Release/anim_pack.exe `
  --input tests/fixtures/anim_pack/simple_rig.glb `
  --out-dir build_pack/anim_out `
  --manifest tests/fixtures/anim_pack/simple_rig_manifest.json `
  --events tests/fixtures/anim_pack/simple_rig_events.json
build_pack/tools/anim_pack/Release/anim_pack_demo.exe `
  --manifest build_pack/anim_out/simple_rig_manifest.json `
  --clip-name Walk --seconds 1 --samples 4
```

插值映射：

| glTF | `.ab` |
|------|-------|
| `LINEAR` | 中心差分写入 `inSlope/outSlope` |
| `STEP` | 左侧关键帧 `constant=true` |
| `CUBICSPLINE` | in/out tangent 直接映射到 `inSlope/outSlope` |

四元数逐关键帧做半球连续性修正；`--coordinate mirrored` 对 rest local、inverseBind、
translation/rotation 与 CUBICSPLINE 切线做一次性 Z 镜像，双次镜像恢复原值。

事件 sidecar（Blender Marker 不会写进 glTF）：

```powershell
blender -b character.blend --python tools/blender/export_events.py -- `
  --output build/anim/events.json --strip-action-prefix "Armature|"
```

sidecar 为每个 Action 保存 `frameStart/frameEnd` 和 `{frame, name}`；packer 按
`(frame-frameStart)/(frameEnd-frameStart)` 换算并覆盖 manifest 中同 Action 的
`events`，未匹配到任何 manifest Clip 的 Action 会报错。脚本也支持
`--self-test`，不需要 Blender 即可检查换算。

打包后的播放验收（headless，不需要 bgfx）：

```powershell
build_pack/tools/anim_pack/Release/anim_pack_demo.exe `
  --skeleton build/anim/character.skeleton.json `
  --clip build/anim/Walk.ab --seconds 1 --samples 4
```

`anim_pack_demo` 使用运行时 `HobiAnimator`/`ClipTransition`，并演示
`RootMotionToTransform` 消费根运动。manifest 模式直接验证运行时事件和根骨绑定：

```powershell
build_pack/tools/anim_pack/Release/anim_pack_demo.exe `
  --manifest build/anim/anim_manifest.json `
  --clip-name Walk --seconds 1 --samples 4
```

`AnimationClipLibrary` 共享 `.ab`，`AnimationTransitions` 为每个角色建立独立的
`ClipTransition`/`EventSequence`；`play` 会按 manifest 的 `rootBone` 设置根运动骨骼，
事件回调由 `EventCallbackMap` 按名称绑定。

### 13.1 同骨架端到端与视觉验收（P8.6）

真实 Blender 资产使用同一套命令，只把输入换成 `character.glb` / `character.blend`：

```powershell
blender -b character.blend --python tools/blender/export_events.py -- `
  --output build_pack/anim_out/events.json --strip-action-prefix "Armature|"
build_pack/tools/anim_pack/Release/anim_pack.exe `
  --input character.glb `
  --out-dir build_pack/anim_out `
  --manifest anim_manifest.json `
  --events build_pack/anim_out/events.json
build_pack/tools/anim_pack/Release/anim_pack_demo.exe `
  --manifest build_pack/anim_out/anim_manifest.json `
  --clip-name Walk --seconds 2 --samples 8
```

视觉截图需要同一 Blender rig 的模型（`bgfx_demo` 不做骨骼自动重映射），命令模板见
`docs/18` §8.5；检查脚底接触、循环首尾、根运动方向和 Marker 时间点。仓库目前只提交
合成 `simple_rig.glb`，因此已完成的验收是 **数据/运行时链路**；真实 Blender 视觉签字
需要美术提供资产后执行。

当前基线：主构建 **290/290**，`ANIM_BUILD_ANIM_PACK=ON` **303/303**，EnTT **291/291**。
若源动画与目标骨架不同，可使用 P9 可选的 `RetargetClipTransition`（见 `docs/18` §9）；
它仍要求源 `BoneLocalClip`、源/目标 `HumanoidAvatar` 和真实资产的视觉验收。
