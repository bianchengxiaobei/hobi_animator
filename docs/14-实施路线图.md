# 14 · 实施路线图

按“先底层后上层、先通用后人形、每步可验证”的顺序推进。每个阶段都定义**可执行的验收标准（DoD）**。

> 范围与验收基准：[17-功能范围与验收](17-功能范围与验收.md)。本文记录各阶段任务与历史 DoD；如与 17 冲突，以 17 为准。
>
> 原则：**功能可验证才继续**。优先使用现有 Unity 4.7 离线 fixtures、功能测试和视觉验收；Unity 2019 数值对拍为可选精确模式，不作为发布阻塞。

## 阶段总览

## 关键依赖与顺序理由

1. **P0 曲线求值**是一切的基础——曲线不对，后面全错。所以必须先单独对拍。
2. **P1 通用骨骼**比人形简单，用来验证骨架/位姿/根运动管线。
3. **P2 图**独立于具体 Clip 语义，可先用手写 Pose 验证混合。
4. **P3 门面**把图包装成 Hobi 语义，是 P4 的宿主。
5. **P4 人形**依赖 P1（骨架）与 P3（状态/层），且必须用 P6 的样本或手写数据；但转换器可以晚于 P4（P4 可先用手工构造的肌肉样本）。
   - 若想更早拿到真实数据：把 P6 的“解析器 + .ab”提前到 P4 之前（推荐，能直接用 `Humanoid-Walk.anim`）。
6. **P5/P6/P7** 相对独立，可在 P4 标定期间并行。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 曲线加权切线语义与 Unity 不符 | 全盘误差 | P0 立即对拍；以 Unity 输出为准 |
| 肌肉 pre/post/limit 标定困难 | 人形姿态错 | 单骨单轴最小用例二分；黄金数据 |
| 混合四元数顺序/归一化差异 | 混合抖动/偏差 | 对拍 Pose；固定参考四元数策略 |
| 事件正/反向/循环边界 | 重复/漏触发 | 对拍事件时刻；照抄 EventDispatcher 状态机 |
| 手性/坐标不一致 | 渲染错乱 | 集成层统一转换；demo 校验 |
| 每帧分配/性能 | 卡顿 | 池化 + 预分配；profile 门槛 |
| 转换器 YAML 兼容 | 资源无法导入 | 定向解析器；批量回归现有 17 个 clip |
