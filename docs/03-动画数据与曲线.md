# 03 · 动画数据与曲线

本层（L2）定义动画如何存储与采样。必须与原项目的**底层数据语义**一致，因为所有上层行为（播放、混合、事件）都建立在其上。

## 1. 曲线（Curve）

Unity 把一个通道（如某骨骼的某一分量、或某根肌肉）存成一条 `AnimationCurve`，内部是**关键帧数组**。`.anim` 中每个关键帧的字段（见 `Examples/Art/Humanoid Animations/Humanoid-Walk.anim:22-31`）：

```
serializedVersion: 3
time, value, inSlope, outSlope, tangentMode, weightedMode, inWeight, outWeight
```

`include/anim/clip/Curve.h`

```cpp
struct Keyframe {
    float time = 0;
    float value = 0;
    float inSlope = 0;     // 左切线（斜率，dy/dx）
    float outSlope = 0;    // 右切线
    float inWeight = 1.f/3.f;
    float outWeight = 1.f/3.f;
    uint8_t tangentMode = 0;   // 位标记：Free/Auto/Linear/Constant/Weighted
    uint8_t weightedMode = 0;
    bool constant = false;     // 本关键帧 -> 下一关键帧为常量段
};

class Curve {
public:
    std::vector<Keyframe> keys;   // 按 time 升序
    float length() const;         // keys 存在时最后一个 time，否则 0
    float evaluate(float t) const;
    float evaluateUnclamped(float t) const;   // 循环/外插由 Clip 处理
};
```

### 1.1 求值语义（必须与 Unity 对齐）

相邻两关键帧 `k0(t0,v0,m0)`, `k1(t1,v1,m1)`，令 `dt=t1-t0`, `u=(t-t0)/dt`：

- **非加权（weightedMode 关闭）**：标准三次 Hermite
  ```
  h00 = 2u³-3u²+1
  h10 = u³-2u²+u
  h01 = -2u³+3u²
  h11 = u³-u²
  v = h00*v0 + h10*dt*k0.outSlope + h01*v1 + h11*dt*k1.inSlope
  ```
- **加权（weighted tangents）**：把斜率+权重转换为贝塞尔控制点后做 De Casteljau，控制点方向=切线方向、长度由 `inWeight/outWeight`（0..1）决定：
  ```
  c1 = p0 + (dt/3) * k0.outWeight * (1, k0.outSlope)
  c2 = p1 - (dt/3) * k1.inWeight * (1, k1.inSlope)
  ```
- 首帧之前 = `v0`（Constant 前外插）或按 `m_PreInfinity`；尾帧之后同理（`m_PostInfinity`）。
- `tangentMode` 为位标记（Free/Auto/Linear/Constant + Weighted）。**Constant** 段直接取左值。

> ⚠ 上述加权公式与位标记的精确行为**以黄金数据为准**（见 13）。P0 实现后用 `SpiderBot-*.anim`（generic，`m_Local*` 通道）逐帧对拍，误差 `<1e-4` 才算通过。若不一致，以原项目实际输出为准修订本公式。

### 1.2 实测数据与实现细节（P0）

对 `Examples/Art` 下全部 **13 个 `.anim`** 做了统计：

| 项 | 实测值 | 结论 |
|----|--------|------|
| `weightedMode` | 全部为 `0` | 示例资源**不含加权切线**；加权路径只能用手工数据/Unity 生成数据验证 |
| `tangentMode` | `0`(6579) / `34`(8721) / `136`(6) | 均为成对切线且带显式 `inSlope/outSlope` |
| `m_PreInfinity` / `m_PostInfinity` | 全部为 `2` | `WrapMode::Loop` |
| `m_LoopTime` | `1`(9 个) / `0`(4 个) | 由 Clip 层决定是否循环 |

由此确定 P0 的实现取舍：

1. **求值一律以存储的 `inSlope/outSlope` 为准**（Hermite）。`tangentMode` 只是编辑器元数据；
   运行时不需要根据它重算切线（Unity 的序列化数据已经给出最终切线）。
2. **不猜 `tangentMode` 位布局**：`Keyframe::constant` 由转换器在 P6 依据 Unity 的位域精确解码后设置；
   示例资源中没有常量段，P0 用手工数据验证 `constant=true` 的 hold 行为。
3. `Curve` 保存 `preWrap/postWrap`（来自 `m_PreInfinity/m_PostInfinity`），并提供
   `evaluate()`（按 wrap）、`evaluateClamped()`、`evaluateUnclamped()`（Hermite 参数延拓）。
4. 加权实现：`c1 = p0 + (dt/3)·w0·(1, outSlope)`、`c2 = p1 - (dt/3)·w1·(1, inSlope)`，
   再对 x 反解贝塞尔参数（牛顿 + 二分兜底）。
5. P0 校验方式：`Humanoid-Walk` 的 `RootT.x` 真实关键帧 + **双精度参考实现**逐点对拍 `<1e-5`；
   Unity 运行时 oracle 属于可选精确模式，默认以真实关键帧 + 双精度参考回归为准（见 [17](17-功能范围与验收.md)）。

## 2. 事件标记

动画自身可带 `AnimationClip.events`（原项目 `AnimancerEvent.Sequence.AddAllEvents`，`AnimancerEvent.Sequence.cs:1140`）。本库在 Clip 中存 `EventMarker{ time(normalized), name }`，加载时由上层可选地转成运行期回调（见 07 事件章节）。

## 3. Clip 类型

`include/anim/clip/Clip.h`

```cpp
enum class ClipType : uint8_t { BoneLocal = 0, HumanoidMuscle = 1 };

struct EventMarker { float normalizedTime; StringId name; };

// 非骨骼命名浮点通道（Unity 属性曲线），见 10 §8。
struct PropertyChannel { StringId path; StringId attribute; Curve curve; };

struct Clip {
    ClipType type;
    float length = 0;
    bool looping = false;
    float averageSpeed = 0;          // 对应 AnimationClip.averageSpeed
    std::vector<EventMarker> markers;
    std::vector<PropertyChannel> properties;
    virtual ~Clip() = default;
};
```

### 3.1 BoneLocalClip（通用骨骼动画）

来源：`.anim` 中带 `path` 且 `attribute` 为 `m_LocalPosition/m_LocalRotation/m_LocalScale` 的通道
（见 `Examples/Art/Spider Bot/SpiderBot-MoveUp.anim` 的 `path: Root/RightUpperLeg` + `m_LocalRotation.x`）。

```cpp
struct BoneChannel {
    int boneIndex;     // 目标骨架中的骨骼索引（转换期建立 path->bone 绑定）
    Curve position[3]; // x,y,z（可缺省）
    Curve rotation[4]; // x,y,z,w
    Curve scale[3];
    uint8_t hasPosition:1, hasRotation:1, hasScale:1;
};

struct BoneLocalClip : Clip {
    std::vector<BoneChannel> channels;
    void sample(float t, Pose& out, const Skeleton& sk) const; // 见 04
};
```

未出现的骨骼保持 rest pose（由采样器从 Skeleton 默认值填充）。

### 3.2 HumanoidClip（人形肌肉空间）

来源：`.anim` 中 `attribute` 为肌肉名/`RootT/RootQ/LeftFootT/...` 的通道
（见 `Humanoid-Walk.anim:62` `RootT.x`、`:370` 附近 `Spine Front-Back`、手指 `LeftHand.Thumb.1 Stretched`）。

```cpp
struct HumanoidClip : Clip {
    // 95 个肌肉 DOF，另有 root/hand/foot 的 T/Q 曲线
    std::vector<Curve> muscles;   // 索引 = MuscleId（见 05）
    Curve rootT[3];               // RootT.x/y/z
    Curve rootQ[4];               // RootQ.x/y/z/w
    Curve leftFootT[3], rightFootT[3], leftFootQ[4], rightFootQ[4];   // IK goals
    Curve leftHandT[3], rightHandT[3], leftHandQ[4], rightHandQ[4];   // IK goals
    bool hasFootQ=false, hasHandQ=false;
    // 运行期通过 MuscleSpace::toLocal 转成 Pose（见 05）
};
```

肌肉名称与 `MuscleId` 的映射表是固定的（Unity humanoid 规范），详见 [05](05-人形肌肉空间与重定向.md)。

## 4. `.ab` 二进制格式（自定义）

离线转换器（见 11）把 `.anim` 转成 `.ab`。布局：

```
Header:
  char magic[4] = 'A','B','N','1'
  u16 version            // 当前 = 3
  u16 clipType
  u32 flags              // bit0: looping；bit1..6: humanoid 的 Root/Foot/Hand 存在标志
  f32 length
  f32 averageSpeed
  u32 stringTableCount   // 预留（当前写 0）
  u32 boneCount          // BoneLocal 时有效
  u32 channelCount
  u32 muscleCount
  u32 markerCount
  u32 propertyCount      // v3 起；非骨骼属性通道数量
StringTable:
  [u32 len][bytes] * stringTableCount   // 预留
Channels (BoneLocal):
  per channel: i32 boneIndex, u8 mask,   // bit0 pos, bit1 rot, bit2 scale
               [curve] * popcount(mask)
Curves:
  u8 preWrap, u8 postWrap, u16 reserved
  u32 keyCount
  per key: f32 time, f32 value, f32 inSlope, f32 outSlope,
           f32 inWeight, f32 outWeight, u8 tangentMode, u8 weightedMode,
           u8 constant, u8 reserved
Muscles (Humanoid):
  curve rootT *3, rootQ *4, muscles *muscleCount,
  optional footT *6, footQ *8, handT *6, handQ *8
Markers:
  per marker: f32 normalizedTime, u64 stringId（FNV-1a hash）
Properties (v3):
  per property: u64 pathHash, u64 attributeHash, curve
```

要求：
- 所有浮点为 f32；文件头显式版本，便于后续加压缩/量化。
- 曲线按时间升序；结构体按 4 字节对齐以直接 mmap/原地读取。
- 可选压缩（明确不在当前版本范围）：关键帧量化 + delta 编码，但**接口不变**；需要时按 17 的变更流程评估。
- `preWrap/postWrap` 与 `constant` 必须持久化，否则读回后外插/常量段语义会变。
- 版本 1 未持久化 wrap/constant，已废弃；读取器接受 **v2/v3**，v3 增加
  `propertyCount` 与属性通道。空路径的属性用 `pathHash = 0`。

## 5. 采样 API

```cpp
// 在 t 秒处采样，循环由上层（AnimancerState）根据 t 是否越界决定是否 wrap。
void sampleClip(const Clip& clip, float t, const Skeleton& sk,
                const HumanoidAvatar* avatar, Pose& out);
```

- BoneLocal：逐通道 `curve.evaluate(t)` 写入 `out.local[boneIndex]`，其余保持 `sk.restLocal`。
- HumanoidMuscle：先采样 95 肌肉 + root + IK goal，再 `MuscleSpace::toLocal(...)`（05）。
- `t` 的 wrap/拍数计算由 `AnimancerState`（07）负责，本层不处理循环语义。

## 6. 与原项目对照

| 本库 | 原项目 |
|------|--------|
| `Curve` / `Keyframe` | Unity `AnimationCurve`（数据来自 `.anim m_Curve`） |
| `BoneLocalClip` | `ClipState` 所播放的 `AnimationClip`（generic） |
| `HumanoidClip` | `ClipState` 所播放的 `AnimationClip`（humanoid muscle space） |
| `EventMarker` | `AnimancerEvent.Sequence.AddAllEvents(AnimationClip)` (`AnimancerEvent.Sequence.cs:1149`) |
| `sampleClip` | 引擎内部 `AnimationClipPlayable` 的采样（黑盒，本库自实现） |

> 原项目把采样交给闭源引擎；本库必须自己实现——这是与 Unity 差异最大的部分，默认用真实关键帧 + 双精度参考 + Unity 4.7 离线 fixtures 验证，Unity 2019 oracle 为可选精确模式。
