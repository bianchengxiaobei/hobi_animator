# 19 · 调试、校验与参考查看器规划

> 状态：D1.1-D1.3（离线校验工具）、D2.1-D2.2（运行时快照）、D3（事件观察者、Recorder）、D4（bgfx 参考查看器）与 D5（只读预览）均已实现。
> 本文是后续分步实现的依据。
> 目标读者：自研 C++ 引擎的运行时/工具链开发者。
> 范围基准：[17-功能范围与验收](17-功能范围与验收.md)；本文只补充**调试、校验与参考查看器**，不改变 17 的范围结论。
> 原版参考：Unity 工程 `Assets/Plugins/Animancer/Internal/Editor/`（下文简称“原版编辑器”）。
> 结论：**不做产品级编辑器**；做离线资产校验、运行时只读调试接口、bgfx 参考查看器三件套。

## 1. 结论先行

原版 Animancer 的编辑器价值主要来自 Unity 生态：Inspector、SceneView、AnimationClip 预览、
Sprite 批处理。这些能力移植到 C++ 多引擎运行时后，UI 不能复用，目标引擎又都有自己的编辑器，
因此**复刻编辑器的投入产出比很低**。

当前项目真正需要解决的是另外三件事：

1. **资产进引擎前就能发现结构错误**：骨骼索引越界、事件时间非法、manifest 引用了不存在的
   `.ab`、根骨名不存在等。这类问题在集成到其他引擎后通常表现为“动作不对/没反应”，排查成本高。
2. **运行时状态可观察**：当前 layer、state、weight、fade、time、speed、事件是否按预期工作。
   宿主引擎需要拿到的是**数据**，不是某套固定 UI。
3. **有一个可运行的参考查看器**：用于本仓库验收、向引擎团队演示接线方式，以及快速定位
   “资产对但播放不对”还是“播放对但渲染不对”。

因此本文的交付物是：

| 交付物 | 形态 | 是否依赖 bgfx/UI | 阶段 |
|--------|------|------------------|------|
| `anim_validate` | 离线 CLI + 机器可读 JSON 报告 | 否 | D1 |
| `anim_debug` | 引擎无关的只读快照 API / 静态库 | 否 | D2/D3 |
| `bgfx_demo` 参考查看器 | 示例程序内的文字 overlay + headless 快照 | 是（仅 sample） | D4 |
| Transition/Clip 预览模式 | 查看器内的只读预览 | 是（仅 sample） | D5（已完成） |

**不做**：Unity 式 Inspector、Transition Preview 窗口、Animancer Tools 窗口、可视化状态机编辑、
曲线编辑、Sprite 批处理。若未来确有“策划/美术要在目标引擎里日常调动画”的需求，应该做**目标引擎
插件**，而不是独立编辑器；见 §14。

## 2. 范围与约束

### 2.1 目标

- 资产校验覆盖 `.ab`、`skeleton.json`、`anim_manifest.json` 三者的单独与交叉检查。
- 运行时提供只读快照：图、层、状态、权重/时间/速度、事件、根运动。
- 事件派发可被记录，用于回答“事件到底有没有触发、何时触发、方向对不对”。
- 参考查看器可以交互播放/暂停/单步/切 clip，并显示状态面板；同一套数据可 headless 导出 JSON。
- 所有调试能力**可裁剪**：不链接 `anim_debug` 时，运行时核心不引入额外依赖和每帧成本。
- 保持现有主构建 290 / `anim_pack` 303 测试通过；新增测试与文档同步更新。

### 2.2 非目标

- 不实现 Unity Editor、Inspector、菜单、EditorWindow、Undo/SerializedProperty。
- 不实现动画剪辑/曲线/状态机的**编辑与保存**；所有工具只读，校验器只写报告。
- 不引入 ImGui、Qt、SDL 等 UI 依赖；D4 使用 bgfx 自带 debug text。
- 不修改 `.ab` 二进制格式；不为调试给 `Clip`/`Skeleton` 增加名称字段。
- 不把调试接口绑到 bgfx、assimp、EnTT 或任何线程池实现。
- 不复制原版 Animancer Tools 的 Sprite/Texture 工具（这些应留在 Blender/DCC 侧）。

### 2.3 硬约束

1. `include/anim/**` 与 `src/**` 仍只依赖 glm；`anim_debug` 是独立静态库，不能反向污染核心依赖。
2. `include/anim/**` 与 `src/**` 禁止包含 bgfx/assimp；overlay 代码只能出现在 `samples/bgfx_demo/`。
3. 校验器不得重新实现 `.ab` / JSON 解析，必须复用现有入口：
   - `anim::decodeClip`（`include/anim/clip/ClipIO.h`）
   - `anim::converter::loadSkeletonFile`（`tools/anim_converter/SkeletonLoader.h`）
   - `anim::loadAnimationManifest`（`include/anim/integration/AnimationManifest.h`）
4. 记录器在预分配后不得每帧分配；快照导出（`std::string`/JSON）可以分配，但只能在显式调用时发生。
5. 调试数据只在拥有 `HobiPlayable` 的线程上采集；跨线程采集不在本规划内。
6. 所有输出（报告、快照）必须带 `version`，字段顺序稳定，便于 CI 比对。

## 4. 总体架构

```text
离线：
  .anim / .glb
      │ anim_converter / anim_pack
      ▼
  *.ab + *.skeleton.json + anim_manifest.json
      │
      ▼
  anim_validate (D1) ──> validation-report.json
      │  (ok / error / warning)

运行时：
  HobiAnimator / HobiPlayable
      │
      ├─ anim_debug::capture() ──> Snapshot ──> JSON（D2）
      │
      ├─ IEventObserver + DebugRecorder ──> 帧历史 + 事件环（D3）
      │
      └─ 宿主引擎自己的调试面板
                 ▲
                 │ 可选
  bgfx_demo DebugOverlay（D4）：读取 Snapshot/Recorder，只负责显示
```

设计原则：

- **数据与展示分离**：D2/D3 只产出结构体/JSON，不假设 UI；bgfx overlay 只是其中一个消费者。
- **核心与工具分离**：`anim_debug` 链接 `anim`，但 `anim` 不链接 `anim_debug`；不链接时零成本。
- **离线优先**：能在资产阶段发现的问题，不留给运行时；D1 先于 D2/D4。
- **只读**：校验器只写报告，查看器只改内存中的播放状态（不落盘、不改 `.ab`/manifest）。

## 5. D1 · 离线资产校验（最高优先）

### 5.1 目标

新增 `anim_validate`，对“将要进引擎的资产”做结构校验，并输出机器可读报告。
它不替代 `anim_converter`/`anim_pack` 的自检，而是补上**跨文件、跨资产**的检查：

- `.ab` 能否解码，内部通道是否合法；
- `skeleton.json` 是否拓扑有序、骨数是否与 clip 匹配；
- `anim_manifest.json` 引用的文件是否存在、事件/根骨/loop 配置是否一致；
- 同一份 manifest 下的 clip 是否互相矛盾。

### 5.2 CLI 草案

```text
anim_validate --manifest anim_manifest.json
              [--skeleton character.skeleton.json]
              [--asset-root build/anim_out]
              [--json validation-report.json]
              [--strict]
              [--quiet]

anim_validate --ab Walk.ab
              [--skeleton character.skeleton.json]
              [--json report.json]
              [--strict]
```

约定：

- `--manifest` 与 `--ab` 至少给一个；`--ab` 可重复；给 `--manifest` 时自动遍历其中所有 `clips[].file`。
- `--skeleton` 省略时，若 manifest 有 `skeletonFile`，按 asset root 解析并加载；
  直接 `--ab` 且没有 skeleton 时只做不依赖骨数的检查，并输出 `info` 提示。
- `--asset-root` 作为 manifest 引用路径的基准，默认是 manifest 所在目录。
  `--skeleton` 的相对路径默认按当前工作目录；显式给 `--asset-root` 时按 asset root。
- 退出码：`0` 无 error；`1` 有 error，或 `--strict` 下有 warning；`2` 参数/IO 错误。
- 默认把人类可读摘要写 stdout，`--json` 写完整报告；`--quiet` 只保留退出码。
- 不在本阶段自动修改任何资产。

### 5.3 校验规则

规则分三级：`error`（资产不可用）、`warning`（可疑但可运行）、`info`（统计）。
`--strict` 把 warning 视为失败。

| 类别 | error | warning / info |
|------|-------|----------------|
| 容器/IO | `.ab` magic/version 错误、截断、意外 EOF；manifest/skeleton JSON 解析失败 | 文件扩展名与内容不符 |
| Clip 基础 | `length` 非有限或 < 0；`averageSpeed` 非有限；类型未知 | 零长度（合法但可疑）；无任何通道；平均速度与 length 不匹配 |
| 骨骼通道 | `boneIndex < 0` 或 >= 骨架骨数；同一骨重复通道 | 某骨只有 position 没有 rotation/scale（合法但可疑）；空曲线 |
| 曲线 | 关键帧时间为 NaN/Inf；关键帧时间不升序；旋转四元数曲线全零 | 关键帧时间重复；加权切线与 tangentMode 组合可疑 |
| 人形 | humanoid clip 的 muscle 索引越界；RootT/RootQ 标志与曲线数量矛盾 | 缺失 goal 曲线；肌肉曲线为空 |
| 事件 | marker `normalizedTime` 不在 `[0,1]`；事件名为空 | 事件重复（同名/同时刻）；manifest 事件与 `.ab` marker 不一致；End 事件无回调 |
| 骨架 | 空骨架；骨名/`StringId` 重复；parent 非法或非拓扑序；rest TRS/逆绑定矩阵非有限 | 根骨不唯一；骨骼数量异常（仅提示） |
| Manifest | 缺少 `name`/`file`；同名 clip/action 重复；文件不存在；`rootBone` 不存在；`loop`/`fade`/`speed`/`start` 非法 | manifest 的 `skeletonFile` 不可读（命令行已提供 skeleton 时）；事件名在 clip 中不存在 |
| 交叉 | 任一通道 `boneIndex` 超出骨架范围；manifest 引用的 skeleton 与命令行 skeleton 内容不一致 | clip 只覆盖部分骨骼（正常）；`.ab` 类型与是否使用 avatar 不一致；coordinate 未识别 |
| 安全/可移植性 | 资产路径逃逸 asset root（`..`）且无法定位 | 绝对路径虽可用但不利于换机；asset root 外的路径提示 |

> 规则来源：`Clip`/`Skeleton` 的数据约束见 [03](03-动画数据与曲线.md)、[04](04-骨架与位姿.md)；
> manifest 字段约束见 [18](18-Blender资产管线与运行时补齐.md)；
> 可开关警告的语义参考原版 `OptionalWarning.cs`，但本库只保留与资产相关的部分。

D1.2-D1.3 已实现的稳定 code：`ab.magic` / `ab.version` / `ab.truncated` / `ab.type` /
`ab.decode` / `ab.io`，`clip.length_invalid` / `clip.length_zero` / `clip.average_speed_invalid` /
`clip.bone_index_*` / `clip.channel_*`，
`curve.key_*` / `curve.rotation_zero` / `curve.empty`，`event.time_range` / `event.name_invalid` /
`event.duplicate`，`skeleton.*`，`manifest.*`。测试断言这些 code，UI/文案可后续调整。

### 5.4 报告格式

```json
{
  "version": 1,
  "ok": false,
  "strict": true,
  "summary": {
    "files": 3,
    "clips": 2,
    "errors": 1,
    "warnings": 2
  },
  "issues": [
    {
      "severity": "error",
      "code": "clip.bone_index_range",
      "file": "Walk.ab",
      "clip": "Walk",
      "path": "channels[72].boneIndex",
      "message": "boneIndex 120 is out of range for skeleton with 54 bones"
    },
    {
      "severity": "warning",
      "code": "manifest.event_missing",
      "file": "anim_manifest.json",
      "clip": "Walk",
      "path": "clips[0].events[2].name",
      "message": "event 'FootFall' is not present in Walk.ab markers"
    }
  ],
  "stats": {
    "clips": {
      "Walk": { "length": 1.0, "channels": 54, "markers": 2, "events": 2 }
    }
  }
}
```

实现约定：

- `issues` 按 `severity`（error→warning→info）、`file`、`clip`、`path` 排序，保证 diff 稳定。
- `code` 是稳定的机器标识，文案可变；测试断言 `code`，不要断言完整 message。
- 单个文件失败不中断其他文件；汇总后统一返回。
- `.ab` 的名称来自 manifest；直接 `--ab` 模式没有名称，报告 `clip` 字段用文件名。

## 6. D2 · 运行时快照 API

### 6.1 形态选择

新增独立静态库 `anim_debug`（可选构建）：

```cmake
option(ANIM_BUILD_DEBUG_TOOLS "Build runtime debug snapshot/recorder" ON)
if(ANIM_BUILD_DEBUG_TOOLS)
    add_library(anim_debug STATIC
        src/debug/Snapshot.cpp
        src/debug/JsonReport.cpp
        src/debug/Recorder.cpp)
    add_library(anim::debug ALIAS anim_debug)
    target_link_libraries(anim_debug PUBLIC anim::anim)
endif()
```

- 默认 ON，方便仓库内测试/查看器；引擎侧可 `-DANIM_BUILD_DEBUG_TOOLS=OFF` 完全不编译。
- 核心库 `anim` 不链接 `anim_debug`；核心头文件也不 include debug 头。
- 快照是**按需调用**：`capture()` 可以分配；`captureInto()` 复用调用方 `Snapshot` 的容量，
  层/状态数量稳定时不新增堆分配。overlay 必须用后者或限频，不能每帧 `capture()` 产生垃圾。

## 7. D3 · 帧记录与事件日志

### 7.1 为什么需要 core 侧钩子

只读轮询 `HobiState::events()` 无法知道事件是否真的被派发（尤其是循环、反向、End 每帧触发）。
原版 `EventDispatcher` 在 post-update 里决定触发哪些事件；本库对应实现是
`src/hobi/EventDispatcher.cpp`。因此需要在**派发点**加一个轻量观察者钩子。

约束：

- 钩子不能依赖 `anim_debug`；定义在核心 `include/anim/hobi/EventObserver.h`。
- 钩子指针为空时只有一次空指针判断；不分配、不加锁、不抛异常。
- 事件回调本身仍按现有顺序执行；观察者只“旁听”，不能修改 state/事件序列，也不能改变派发结果。
- 通知放在用户回调**之前**，此时 state 仍有效；不要依赖“回调执行后状态仍然存在”
  （回调可能 stop/切换/销毁状态）。

```cpp
// include/anim/hobi/EventObserver.h
namespace anim {

enum class EventKind : uint8_t {
    Normal = 0,
    End = 1,
};

class IEventObserver {
public:
    virtual ~IEventObserver() = default;

    // 在事件实际 invoke 之前调用（此时 state 仍有效）。
    // state 的 events() 仍可读；eventIndex 对 End 事件为 -1。
    virtual void onEventDispatched(const HobiState& state,
                                   const HobiEvent& event,
                                   EventKind kind,
                                   int eventIndex,
                                   bool playingForwards) = 0;
};

}  // namespace anim
```

接入点：

- `HobiPlayable` 增加 `setEventObserver(IEventObserver*)` / `eventObserver()`。
- 新状态创建/重新设置 dispatcher 时，把 observer 传到 `EventDispatcher`；
  状态销毁时清空，避免悬空。
- `EventDispatcher` 在 `invokeAllEvents` / `nextEvent` 实际调用处通知；
  End 事件通知 `kind=End, eventIndex=-1`，普通事件通知其在 `EventSequence` 中的下标。
- 观察者不持有 state 的生命周期；如果需要异步使用，必须自行拷贝需要的数据。

> 备选方案（不采用）：给每个事件包一层回调。它无法可靠区分 End/普通事件，且会改变用户回调的
> 身份与 `EventSequence` 语义，故放弃。

### 7.2 Recorder API（D3.2 已实现）

```cpp
// include/anim/debug/Recorder.h
namespace anim::debug {

struct RecorderConfig {
    int frameCapacity = 300;   // 环形帧数
    int eventCapacity = 256;   // 事件环大小
};

struct StateSample {
    int layer = -1;
    int indexInLayer = -1;
    PlayableHandle playable{};
    double time = 0.0;
    float weight = 0.0f;
    float targetWeight = 0.0f;
    float speed = 1.0f;
    bool playing = false;
};

struct LayerSample {
    int index = 0;
    float weight = 0.0f;
    float targetWeight = 0.0f;
    int currentState = -1;
};

struct FrameRecord {
    uint64_t frameId = 0;
    float deltaTime = 0.0f;
    float graphSpeed = 1.0f;
    bool graphPlaying = false;
    // 固定容量数组或复用的 vector；attach 时按当前层/状态数 reserve。
    std::vector<StateSample> states;
    std::vector<LayerSample> layers;
};

struct EventRecord {
    uint64_t frameId = 0;
    PlayableHandle statePlayable{};
    int layer = -1;
    int stateIndex = -1;
    int eventIndex = -1;
    EventKind kind = EventKind::Normal;
    float normalizedTime = 0.0f;
    bool playingForwards = true;
    uint64_t eventNameHash = 0;  // 不存 std::string，避免每帧分配
};

class Recorder final : public IEventObserver {
public:
    explicit Recorder(RecorderConfig config = {});
    ~Recorder() override;

    void attach(HobiPlayable& playable);
    void detach();

    // 在 animator.update(dt) 之后调用；不要在 update 之前调用。
    void recordFrame();

    int frameCount() const noexcept;
    int eventCount() const noexcept;
    const FrameRecord* frameAt(int index) const;  // 0 = 最新；负值表示历史
    const EventRecord* eventAt(int index) const;

    // 导出最近 N 帧/事件；会分配，允许。
    std::string toJson(int maxFrames = -1) const;
    bool writeJsonFile(const std::string& path, std::string& error) const;

    // 清空历史但保持容量。
    void clear() noexcept;
};

}  // namespace anim::debug
```

字段与行为：

- `attach` 时按 `playable.layers().count()` 与各层 `childCount()` 预分配；
  `recordFrame` 只更新已有槽位（`clear()` 后仍保留 capacity），不新增字符串。
- `EventRecord` 不复制事件名，只存 `hashString(event.name)`；bgfx 查看器从已加载 manifest
  事件构建 hash→name 映射显示名称，无映射时回退 hash。独立 `Recorder` JSON 仍只含 hash。
- `FrameRecord::states` 的数量随层/状态变化：允许在结构变化时扩容，结构稳定后不再分配。
  文档中明确“无每帧分配”指**稳态**；增删状态/层时允许一次分配。
- `toJson` 输出 `{ version, frames: [...], events: [...] }`；可只导出最近 N 帧，避免长跑爆内存。
  `frames` 项字段与 `FrameRecord` 同名（帧号输出为 `frame`），`events` 项的 `kind` 为
  `"Normal"`/`"End"` 字符串，`statePlayable`/`eventNameHash` 保留原始句柄与哈希。
- 线程：`Recorder` 与 `HobiPlayable` 同线程；不支持并发 attach/record/export。

## 9. D5 · 只读预览模式（已完成）

D5 仍定位为**只读预览**，不是编辑器；复用 `bgfx_demo`，不新增第二套模型/蒙皮代码：

- 选中 manifest clip 后，可在内存中临时修改 fade duration / fade mode / start time / speed / loop；
  不保存、不写回 manifest/`.ab`。
- 播放/暂停/单步；交叉淡入时快照与 overlay 同时显示两个状态的权重、时间、事件。
- 对应原版 `TransitionPreviewWindow.Animations` 的播放控制与动画选择（`PlaySequence`/
  `PlayTransition`/`StepTime`）；不做环境设置、不做场景隔离、不做录制导出。
- headless 验证复用 `bgfx_demo`，不新增 `anim_preview` 工具。

### 9.1 CLI 与交互

```text
--preview-fade seconds
--preview-fade-mode fixed-speed|fixed-duration|from-start|normalized-speed|normalized-duration|normalized-from-start
--preview-start normalized
--preview-speed speed
--preview-loop | --preview-no-loop
--preview-switch-frame N     // headless/截图验收：在第 N 帧切到下一个 clip
```

| 键 | 行为 |
|----|------|
| `F` | 循环 fade duration：0 / 0.1 / 0.25 / 0.5 / 1.0 |
| `M` | 循环 6 种 FadeMode |
| `T` | 循环 normalized start：auto / 0 / 0.25 / 0.5 |
| `-` / `=` | 当前 clip speed -/+ 0.1（0.1–4.0） |
| `L` | 切换 loop |
| `K` | 恢复该 clip 的 manifest 默认值（不改资产） |
| `Up/Down` | 切换 clip（切换时重新应用当前预览配置） |

CLI 预览参数应用到本次加载的 clips；交互修改作用于当前 clip。`F`/`M`/`T` 在下次切换
或 `R` 时应用，speed/loop 立即作用于当前状态。`R`、`Space`、`.`、`[`/`]` 继续使用
D4 语义。所有预览修改只作用于已加载的 `ClipTransition`/`Clip` 内存副本；退出不产生
新的配置文件。

### 9.2 切换与清理

- 切换时调用 `animator.play(transition, fadeDuration, fadeMode)`；使用显式 fade 参数，
  确保 `--preview-fade-mode` 不被 transition 默认值覆盖。
- 旧状态在 fade 权重降到 0 后从 layer 移除并销毁；fade 期间两者都在 D2 快照中，
  fade 结束后旧状态不再出现在 layer/snapshot，也不再派发事件。
- 修复了 `HobiLayer::removeChild` 的内部重连：被移动的末位状态会从旧端口断开、
  在新端口重连并重新标记权重，避免状态销毁后 mixer 输入悬空。新增
  `HobiLayer.DestroyNonLastStateKeepsMovedStateConnected` 回归测试；不改变 D1-D4 API/JSON。
- `Recorder` 中切换前的事件是只读历史；旧状态销毁后不会继续产生新事件。

## 13. 风险与取舍

| 风险 | 影响 | 缓解 |
|------|------|------|
| 需求滑向“做编辑器” | 工期失控、维护 UI | 本文明确只读；D5 也禁止保存/编辑；新增编辑需求另立文档评审 |
| 运行时没有名称字符串 | 日志/overlay 不可读 | `NameResolver`；校验器用 `SkeletonAsset`/manifest；不为此改 `.ab` 格式 |
| 事件钩子改变派发行为 | 事件漏触发/重复 | 旁听接口不返回值；只在 invoke 后通知；用现有事件测试逐项对拍 |
| 记录器每帧分配 | 帧率抖动 | attach 时 reserve；状态结构稳定后只更新槽位；事件只存 hash |
| 快照持有悬空引用 | 崩溃/脏数据 | `Snapshot` 值拷贝；状态用 handle/index；不导出裸指针 |
| overlay 依赖 bgfx | 其他引擎无法复用 | D2/D3 保持引擎无关；overlay 只在 sample，宿主可接自己的 UI |
| headless 快照不可复现 | CI 波动 | 固定 dt/frames；记录 frameId；避免依赖真实时钟/渲染 |
| 校验规则过严 | 正常资产被误杀 | error 只保留“必然无法运行”的规则；主观规则降为 warning；`--strict` 可选 |
| Windows-only 窗口 | 跨平台验收受限 | 查看器是 sample；核心/校验器跨平台；headless 快照不依赖窗口 |
