# 00 · 愿景与范围

## 1. 目标

用 C++ 实现一套完整的骨骼动画运行时，可嵌入自研 C++ 引擎（glm 数学库、bgfx 渲染），在不依赖 Unity 的情况下提供播放、混合、重定向等能力。

核心能力清单（均需实现）：

1. **播放**：单 Clip 播放、时间/归一化时间/速度/暂停、循环。
2. **图与层**：Playable 图、Layer 混合（覆盖 / 加法 / AvatarMask）。
3. **过渡**：Transition 体系、Transition Asset（共享/非共享）、Fade（多种 FadeMode、曲线、Custom Fade）。
4. **状态**：State 层级、StateDictionary（按 key 复用）、weightless 克隆、命中/命令计数。
5. **混合器**：Manual（手动权重）、Linear（1D）、Directional（2D 极坐标）、Cartesian（2D 笛卡尔）。
6. **事件**：事件序列（时间/归一化时间回调、OnEnd、名字索引、正反向触发）。
7. **状态机**：FSM（keyless、WithDefault、InputBuffer、StateChange、StateBehaviour、DelegateState）。
8. **根运动**：从 Hips 提取并重定向到 Transform / 逻辑组件。
9. **Animation Jobs / IK**：过程式节点、TwoBoneIK、Damping、Lean、Animated 属性读取。
10. **人形重定向**：完整肌肉空间（Route A），支持跨比例骨架。
11. **工具链**：`.anim` / `.fbx.meta` 离线转换为自有 `.ab` 二进制。
12. **集成**：主循环驱动、骨骼矩阵调色板输出、bgfx 蒙皮。

## 2. 非目标

- **不**兼容 Unity 运行时 API 或 `PlayableGraph` 原生句柄；我们自己实现等价图。
- **不**要求直接加载 `.anim` YAML（由离线转换器处理）。
- **不**实现 Unity 的 Timeline / `PlayableAsset`、`RuntimeAnimatorController` 的二进制解析。
  - 对应 `PlayableAssetState`、`ControllerState` 的能力，用“自定义 Script 节点”与“Clip 序列”近似替代（详见 07/15）。
- **不**负责渲染、蒙皮着色器、物理。只产出 Pose / 骨骼矩阵调色板。

## 3. 关键约束

1. **功能等价优先**：类职责、权重/淡入淡出/事件/命令计数等算法参考原项目源码；Unity 2019 数值逐帧对拍为可选精确模式（见 [17-功能范围与验收](17-功能范围与验收.md)）。
2. **数学用 glm**：`Vec3/Quat/Mat4` 直接别名到 glm 类型，不重复造轮子。
3. **数据与渲染解耦**：`include/anim/**` 不得包含 bgfx 头文件；渲染接入只发生在 `integration/` 与 `samples/`。
4. **无每帧分配**：热路径（更新、求值、混合）使用对象池/预分配缓冲。
5. **本地可回归**：默认使用 Unity 4.7 离线 fixtures、功能测试和视觉验收；Unity 2019 oracle 仅用于可选精确模式。

## 5. 依赖策略

- **核心库 `anim`**：仅依赖 **glm**；不含渲染、不含 ECS、不含线程池实现。
- **任务调度**：核心只依赖 `IJobScheduler` 抽象；默认 `InlineJobScheduler`（单线程），可选并行后端由集成方注入（见 [16](16-任务调度与ECS集成.md)）。
- **ECS**：**EnTT 为可选依赖**（编译开关 `ANIM_ENABLE_ENTT`），仅用于引擎侧“组件/系统”适配；**EnTT 不是 Job System**（无线程池），并行仍由 `IJobScheduler` 负责。
- **转换器 `anim_converter`**：构建期可依赖 yaml-cpp（或使用自研定向解析器）。
- **测试**：googletest。

## 6. 交付形态

- 一个 CMake 静态库（`anim`），除 glm 外无运行时依赖。
- 一个离线工具 `anim_converter`（可依赖 yaml-cpp，仅构建期使用）。
- 单元测试（googletest）+ 黄金数据对拍。
- 一个 bgfx 最小示例，演示 `Pose -> Mat4 调色板 -> 蒙皮` 的接线。
- （可选）EnTT 适配层。

## 6. 验收总纲

每个里程碑（见 [14-实施路线图](14-实施路线图.md)）都必须满足：
1. 功能测试与 Unity 4.7 离线回归通过（见 [13-测试与黄金数据](13-测试与黄金数据.md)）；Unity 2019 数值对拍为可选精确模式。
2. 公共 API 与 [15-API参考](15-API参考.md) 的“实际签名”及头文件一致。
3. 无每帧堆分配（可用统计/断言验证）。
