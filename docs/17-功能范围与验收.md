# 17 · 功能范围与验收

> 状态：生效中。本文是 hobi_animator 当前**范围与验收的唯一基准**。
> [00-愿景与范围](00-愿景与范围.md)、[14-实施路线图](14-实施路线图.md) 与本文冲突时，以本文为准。
>
> 当前目标不是逐值复刻 Unity 2019，而是做一套**功能等价、可运行、可回归、可视觉验收**的 C++ 动画运行时。

## 1. 目标

### 1.1 Runtime

- Clip 加载、播放、暂停、循环、时间/归一化时间/速度。
- Playable 图、Layer 覆盖/加法/mask、Manual/Linear/Directional/Cartesian 混合器。
- Transition、Fade、CustomFade、EventSequence、End 事件。
- StateMachine、WithDefault、InputBuffer、StateChange、StateBehaviour、StateSelector。
- 便利功能：TimeSynchronizer/TimeSynchronizationGroup、DirectionalAnimationSet(8)/DirectionalClipTransition、
  MixerParameterTween、ExitEvent、DontAllowFade。
- 根运动提取与重定向到 Transform/逻辑目标。
- `AnimatedValue` 属性通道与绑定。

### 1.2 Humanoid

- 95 肌肉表、`preRot/postRot/limits`、muscle ↔ local pose。
- Hips 根空间 `RootT/RootQ` 与 `humanScale`。
- `retargetHumanoidFromPose()` / `retargetHumanoidLocalPose()`。
- 四个 IK goal 采样、两骨 IK 桥接、twist 分配、look-at 桥接。
- 跨比例骨架重定向（至少覆盖离线缩放的同拓扑第二骨架）。

### 1.3 Converter

- `.anim` / `.fbx.meta` / `.avatar` / `skeleton.json` 的离线解析。
- `.ab` v3 读写与 v2 读取兼容。
- 可选 Blender/glTF → `.ab` + skeleton + manifest（`ANIM_BUILD_ANIM_PACK=ON`）。
- Humanoid、Generic BoneLocal、属性通道。
- 批量转换、读回采样自检、17 个现有资源全部可转换。

### 1.4 Jobs / FSM / Integration

- `IAnimationJob`、`InlineJobScheduler`、`ThreadPoolJobScheduler`。
- TwoBoneIK、Damping、SimpleLean、ScriptPoseNode。
- bgfx 调色板输出、GPU 蒙皮 demo、手性转换。
- 可选 EnTT 适配层。

## 2. 非目标

以下能力不属于当前范围，不作为发布阻塞：

- Unity Editor、Inspector、菜单、Editor 工具窗口。
- Unity `ControllerState` / `Float1ControllerState` / `Float2ControllerState` / `Float3ControllerState`。
- Unity `RuntimeAnimatorController` 二进制解析与 Animator 状态机运行时。
- Unity `PlayableAssetState`、Timeline、Unity `PlayableGraph` 原生句柄。
- 原项目的 MonoBehaviour 组件包装。
  - C++ 侧等价物是 `HobiAnimator`，不复制 Unity 组件体系。
- Unity 2019.4 编辑器逐帧黄金数据对拍作为发布门槛。
- 渲染、蒙皮着色器、物理模拟；本库只产出 Pose / 骨骼矩阵调色板。

> 第 1.1 节列出的便利类已纳入当前 P1 范围；其它未列出的 Hobi 便利类不构成当前发布承诺，
> 需要时按第 9 节变更流程加入，不默认阻塞当前版本。

## 3. 已接受的简化

| 项 | 当前实现 | 与 Unity 的差异 | 重新评估条件 |
|----|----------|-----------------|--------------|
| Humanoid Root | 默认 Hips-root：`RootT/RootQ` 覆盖 Hips local；可选 `HumanoidRootMode::MassCenter` 按默认骨质量和肢体朝向计算根，朝向相对 setup/rest，独立 root 骨写目标 mass-root，Hips 经世界空间再转父 local，goal 同步使用 mass-center root | 可选模式与 Unity `RetargetTo` 的逐值 oracle 未覆盖 | 需要逐值对齐 Unity `RetargetTo` 时 |
| FullBodySolve | 保留两骨 IK + twist + look-at 桥接；新增 `applyHumanoidFullBodySolve` 统一入口，mid DoF→测链→IK（共线链 identity 继续）、look-at 与 goal 位置/旋转两阶段顺序已按源码对齐 | 不逐行移植 Unity `FullBodySolve` 的完整迭代 | 现有视觉验收出现明显头/眼/胸姿态问题时 |
| 数值对拍 | 离线 Unity 4.7 fixtures + 自有功能/回归测试 | 不做 Unity 2019 `<0.05°` 全骨逐帧对拍 | 有 Unity 2019 环境且明确需要精确模式时 |
| 第二骨架验证 | 使用离线缩放的同拓扑骨架 | 不是独立的第二个人形资源 | 有真实第二个人形 FBX 时补视觉/功能验收 |

这些简化是**明确的产品决策**，不再作为“未完成 DoD”反复阻塞发布；对应实现细节应继续在文档中保持可追溯。

## 4. 验收分层

### 4.1 功能测试（必须）

- 运行：`ctest --test-dir build -C Debug --output-on-failure`。
- 基线：主构建 **240/240**；开启 `ANIM_BUILD_ANIM_PACK=ON` 时为 **251/251**；
  开启 `ANIM_ENABLE_ENTT=ON` 时为 **241/241**。
- 覆盖：
  - 曲线、Clip、`.ab` 序列化、Pose、混合、调色板；
  - 图、层、Transition、Fade、事件、FSM、StateSelector；
  - TimeSynchronizer/Group、方向动画、MixerParameterTween、ExitEvent、DontAllowFade；
  - State/Layer/LayerList/Playable 的 Clip 收集、`createIfNew`、`StateDictionary::current`；
  - Humanoid 95 肌肉、RootT/RootQ、retarget、goals、IK、twist、look-at；
  - 根运动、Jobs、ThreadPool、Converter、可选 EnTT。
- 新增功能至少新增一个功能单测；性能优化不能只靠 benchmark，必须有结果回归测试。

### 4.2 离线回归（必须）

- 使用现有 Unity 4.7 源码公式生成的 fixtures：
  - `tests/golden/DefaultHumanoid.*.fullbody.json`
  - `tests/golden/DefaultHumanoid.source.avatar.json`
  - `tests/golden/DefaultHumanoid.source.skeleton.json`
  - `tests/golden/spiderbot_data.h`
- 保留 Walk/Run/Idle 各 5 帧 × 54 骨、Hips `RootT/RootQ`、四个 goal 的逐骨回归。
- “自生成 golden”只用于**锁定本实现行为**，不能当作 Unity 正确性证明；若行为变更，必须显式更新 golden 并说明原因。
- 不要求 Unity 2019 Editor、Unity 运行时或 `HumanPoseHandler` 才能跑测试。

### 4.3 视觉验收（发布前必须）

- 使用 Release 构建 bgfx demo：
  - 播放 `Humanoid-Walk.ab`，检查蒙皮、手性、调色板；
  - 播放通用 Clip，检查根运动与循环；
  - 使用缩放后的第二 Humanoid 骨架，检查 retarget 后的姿态、脚底接触、手部 goal；
  - 使用 Blender 同骨架导出的 glTF/FBX 播放 Walk/Run/Idle，检查蒙皮、脚底接触、
    循环首尾和 Marker 事件点（外部资产；命令见 §6.5 与 `docs/18` §8.5）；
  - 保存截图或录屏作为验收证据。
- bgfx 的 Walk/Run/Idle + SpiderBot 截图与命令见 §6.4；retarget 骨架/goal 证据见 §6.3。
- Retarget 场景使用 `humanoid_retarget_demo`（左侧 source，右侧 1.35× target；绿色脚 goal、
  品红手 goal、黄色 actual→goal 连线）。命令与实测结果见 §6.3。
- bgfx Debug 预编译库在本机可能在 `bgfx::init` 挂起，属于环境限制；demo 验收统一使用 Release。

## 5. 支持矩阵

状态说明：

- **已支持**：已有实现和测试覆盖，属于当前交付。
- **可选精确模式**：包括精确数值验证、视觉增强和可选性能优化；均为非阻塞，未来可按需补。
- **明确不支持**：不属于本运行时范围。

### 5.1 运行时

| 能力 | 状态 | 说明 |
|------|------|------|
| Clip 播放/循环/时间/速度 | 已支持 | `ClipState` / `PlayableNode` |
| 图/层/混合器 | 已支持 | Manual/Linear/Directional/Cartesian |
| Transition/Fade/Events/FSM | 已支持 | 含 `ClipTransitionSequence`、自定义 Fade、StateSelector |
| 单 Clip 门面 | 已支持 | `SoloAnimation`：直接采样、播放控制、Pose/Palette |
| 按 Clip/State/Key 播放 | 已支持 | `play(clip/state)`/`tryPlay(key)` 保留状态所属 Layer；`getState(key)` 沿跨层 key 链查找；跨 Layer 播放按原逻辑克隆；`stop(key/clip)` |
| 名字→Clip 门面 | 已支持 | `NamedHobiAnimator`：注册、默认动画、按名字播放/淡入/停止 |
| 便利功能 | 已支持 | TimeSynchronizer/Group、DirectionalAnimationSet(8)、MixerParameterTween、ExitEvent、DontAllowFade |
| 根运动 | 已支持 | Hips-root 语义，见第 3 节 |
| AnimatedValue 属性通道 | 已支持 | `.ab` v3 PropertyChannel |
| TwoBoneIK/Damping/Lean | 已支持 | 功能与几何测试；TwoBoneIK 共线链、Damping 零长度段顺序已对齐；精确 Unity oracle 为可选 |
| ThreadPool/EnTT | 已支持 | EnTT 为可选编译开关 |

### 5.2 Humanoid

| 能力 | 状态 | 说明 |
|------|------|------|
| 95 肌肉 / muscle ↔ local | 已支持 | 含 95 肌肉回代测试 |
| Hips `RootT/RootQ` | 已支持 | 项目约定语义 |
| 跨比例 retarget | 已支持 | 同拓扑缩放验证；真实第二模型为可选精确模式（视觉增强） |
| 跨骨架 BoneLocal retarget | 可选支持 | `RetargetClipState`/`RetargetClipTransition`；目标侧缺失骨按 `HumanPoseAdjustForMissingBones` 迁移；不同拓扑真实资产视觉验收待外部 |
| 四个 goal + 两骨 IK | 已支持 | 不承诺完整 `FullBodySolve` |
| twist / look-at | 已支持 | 桥接实现 |

### 6.3 Humanoid retarget 视觉验收记录

场景：`humanoid_retarget_demo`，使用 `tests/golden/DefaultHumanoid.skeleton.json` 与
`DefaultHumanoid.source.avatar.json`，避免把 FBX 导入尺度/坐标问题混入 retarget 判定。
左侧为 source（hipsHeight=0.963794），右侧为 1.35× target（hipsHeight=1.30112）。
绿色为脚底 goal，品红为手部 goal，黄色线为 actual→goal；地面网格用于目测脚底接触。

```bash
cmake --build build --config Release --target humanoid_retarget_demo
build/samples/bgfx_demo/Release/humanoid_retarget_demo.exe \
  --clips build/ab_test/Humanoid-Walk.ab,build/ab_test/Humanoid-Run.ab,build/ab_test/Humanoid-Idle.ab \
  --clip-frames 120 --screenshot-frame 30 --screenshot build/retarget_acceptance \
  --shaders build/samples/bgfx_demo/Release/shaders --strict
```

截图：

- [Walk](visual-acceptance/retarget-Humanoid-Walk.png)
- [Run](visual-acceptance/retarget-Humanoid-Run.png)
- [Idle](visual-acceptance/retarget-Humanoid-Idle.png)

整段 Clip 的端点误差最大值（目标骨架世界空间，`--goal-tolerance 0.05 m`）：

| Clip | maxFootError | maxHandError | 结果 |
|------|--------------|--------------|------|
| Walk | 0.0332 m | 0.0072 m | PASS |
| Run  | 0.0402 m | 0.0178 m | PASS |
| Idle | 0.0236 m | 0.0137 m | PASS |

`--strict` 退出码为 0；姿态无爆炸，脚底接触与手部 goal 在截图和数值上都成立。脚部残差是
默认两骨 IK 参数下的末端近似误差，不改变本项“可达/无明显滑动”的验收结论。

### 6.4 bgfx mesh/palette 视觉验收记录

场景：Release `bgfx_demo`，默认 `DefaultHumanoid.fbx` + `tests/golden/DefaultHumanoid.source.avatar.json`。
FBX 导入先归一到 runtime 坐标：Assimp `GlobalScale=0.01`（cm→m）、X 轴镜像到 Unity 运行时手性、
合并 `$AssimpFbx$` helper 节点；蒙皮 `inverseBind` 与顶点同步镜像/缩放。结果：

- 模型 88 根骨骼、7813 顶点、38922 索引，75 根蒙皮骨；avatar 映射 54/55 个 human bone。
- 调色板走 `4 × boneCount` RGBA32F 纹理路径（超过 64 根骨骼，不能退回 uniform 数组）。
- 相机用 `--camera-yaw` 选择前 3/4 视角，并跟踪 Hips 根运动；未蒙皮的眼部 mesh 绑定到自身节点骨。

```bash
cmake --build build --config Release --target bgfx_demo
build/samples/bgfx_demo/Release/bgfx_demo.exe \
  --clip build/ab_test/Humanoid-Walk.ab \
  --frames 65 --screenshot build/gate3_walk --screenshot-frame 50 \
  --camera-yaw 25 --shaders build/samples/bgfx_demo/Release/shaders
```

Walk/Run/Idle 使用同一命令替换 `--clip`；默认模型会自动加载 golden avatar。通用 Clip 需先用
demo 导出骨架、再用该骨架转换 `.ab`：

```bash
build/samples/bgfx_demo/Release/bgfx_demo.exe \
  --model "../Assets/Plugins/Animancer/Examples/Art/Spider Bot/SpiderBot.FBX" \
  --export-skeleton build/spider_skeleton.json
build/Release/anim_converter.exe \
  --input "../Assets/Plugins/Animancer/Examples/Art/Spider Bot/SpiderBot-MoveUp.anim" \
  --skeleton build/spider_skeleton.json --output build/spider.ab
build/samples/bgfx_demo/Release/bgfx_demo.exe \
  --model "../Assets/Plugins/Animancer/Examples/Art/Spider Bot/SpiderBot.FBX" \
  --clip build/spider.ab --frames 12 --fixed-dt 0.0333333 \
  --screenshot build/gate3_spider --screenshot-frame 6 \
  --camera-yaw 25 --shaders build/samples/bgfx_demo/Release/shaders
```

非交互截图应使用 `--fixed-dt`（30 fps 为 `0.0333333`，60 fps 为 `0.0166667`）；否则在高帧率
机器上 `--screenshot-frame` 可能只采样到 Clip 开头。

## 7. 可选精确模式

只有在明确需要更高 Unity 一致性或拿到 Unity 2019.4 环境时，才考虑以下工作；它们不进入默认发布门槛：

1. 生成 `HumanoidGolden.json` / `HumanoidFullBodyGolden.json`，恢复 `<0.05°` 全骨对拍。
2. 按 Unity `FullBodySolve` 完整顺序重写 eye/body/neck/head 迭代。
3. 对 TwoBoneIK/Damping 增加逐帧 Unity Job oracle。
4. 评估单图内按链并行、曲线采样和跨骨 SoA。
5. 有真实第二个人形 FBX 时补视觉/retarget 增强回归（不要求逐值对比）。

## 8. 发布门槛

发布前必须同时满足：

1. Release 构建的 `ctest` 全部通过（主构建 240/240；`ANIM_BUILD_ANIM_PACK=ON` 251/251；EnTT 可选 241/241）。
2. 17 个现有 `.anim` 转换与读回通过。
3. bgfx Release demo 能播放通用/人形 Clip 并完成截图验收（已完成，见 §6.4）。
4. Humanoid retarget 视觉场景通过：姿态无爆炸、脚底无明显滑动、手部 goal 可达（见 §6.3）。
5. 文档中的支持矩阵与实际实现一致；未实现项明确标记为“可选精确模式”或“明确不支持”。
6. Blender/glTF 同骨架真实资产的视觉验收通过（§6.5）；当前等待外部 `.blend`/Blender
   导出的 `.glb`，合成夹具不替代该签字。
