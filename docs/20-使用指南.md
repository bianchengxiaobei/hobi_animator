## 2. 构建与测试

### 2.1 依赖

- CMake ≥ 3.20
- C++20 编译器（MSVC 需要 `/utf-8`，根 CMake 已为示例配置）
- 核心库只需要 glm
- 可选：bgfx + assimp（仅 `samples/bgfx_demo`）

### 2.2 最小构建

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

当前基线：主构建 **290/290**；`ANIM_BUILD_ANIM_PACK=ON` **303/303**；EnTT **291/291**；
`ANIM_BUILD_DEBUG_TOOLS=OFF` **278/278**。

### 2.3 常用配置

```powershell
# glTF/GLB 打包器
cmake -S . -B build_pack -DANIM_BUILD_ANIM_PACK=ON
cmake --build build_pack --config Release

# EnTT 适配层
cmake -S . -B build_entt -DANIM_ENABLE_ENTT=ON
cmake --build build_entt --config Release

# 不构建 anim_debug（核心仍可独立使用）
cmake -S . -B build_off -DANIM_BUILD_DEBUG_TOOLS=OFF

# bgfx 查看器（路径按本机修改）
cmake -S . -B build -DANIM_BUILD_SAMPLES=ON `
      -DANIM_BGFX_ROOT=E:/Learn/bgfx `
      -DANIM_ASSIMP_ROOT=E:/Learn/assimp
cmake --build build --config Release --target bgfx_demo
```

`bgfx_demo` 的运行验收使用 **Release**。部分机器的 bgfx Debug 预编译库会在 `bgfx::init` 挂起。

## 3. 在运行时播放动画

### 3.1 加载 Clip

```cpp
#include <fstream>
#include <vector>

#include "anim/clip/ClipIO.h"
#include "anim/hobi/HobiAnimator.h"

std::vector<uint8_t> readFileBytes(const char* path);

auto bytes = readFileBytes("Walk.ab");
std::string error;
std::unique_ptr<anim::Clip> clip = anim::decodeClip(bytes, &error);
if (!clip) {
    // error 包含解码失败原因
    return false;
}

anim::HobiAnimator animator;
animator.initialize(skeleton);  // Skeleton 由引擎导入器提供

animator.play(*clip, 0.25f, anim::FadeMode::FixedSpeed);
```

`Skeleton` 的骨骼顺序必须与 `.ab` 中的 `boneIndex` 一致，且父索引小于子索引。
多数引擎在导入模型时已经构造了骨架；只做同骨架播放时不需要 Humanoid Avatar。

### 3.2 每帧更新

```cpp
void Update(float dt) {
    animator.update(dt);

    const std::vector<glm::mat4>& palette = animator.palette();
    uploadBoneMatrices(palette);  // glm 列主序

    anim::RootMotionDelta delta = animator.consumeRootMotion();
    applyRootMotionIfNeeded(delta);  // 是否应用由宿主引擎决定
}
```

如果使用并行 Job，请在读取 `palette()` 或销毁 Animator 前等待 Job 完成。

### 3.3 Transition、事件与循环

```cpp
anim::ClipTransition transition;
transition.clip = clip.get();
transition.fadeDurationValue = 0.25f;
transition.speedValue = 1.0f;
transition.eventSequence.add(0.5f, [] {
    // FootFall
}, "FootFall");

clip->looping = true;
animator.play(transition);
```

`HobiState` 会引用 `transition.eventSequence`，因此 **Transition 的生命周期至少覆盖状态播放期间**；
不要让包含事件序列的局部 Transition 先于状态销毁。

反向播放时可将 `speedValue` 设为负数；起点/终点默认值由 `EventSequence` 按速度方向决定。

### 3.4 从 manifest 批量加载

```cpp
#include "anim/integration/AnimationClipLibrary.h"
#include "anim/integration/AnimationManifest.h"
#include "anim/integration/AnimationTransitions.h"

anim::AnimationSet set;
if (!anim::loadAnimationManifestFile("anim_manifest.json", set, error)) return false;

anim::AnimationClipLibrary library;
if (!library.load(set, error)) return false;

anim::EventCallbackMap callbacks;
callbacks["FootFall"] = [] { /* ... */ };

anim::AnimationTransitions transitions;
if (!transitions.build(library, callbacks, error)) return false;

anim::HobiState* state = transitions.play(animator, "Walk", &error);
if (state == nullptr) return false;

// manifest 有 rootBone 时，可选绑定根骨
transitions.bindRootBone(animator, "Walk", &error);
```

`AnimationClipLibrary` 和 `AnimationTransitions` 持有 Clip/Transition 内存，应与播放中的 Animator
保持相同的生命周期。

## 4. 资产制作

### 4.1 Unity `.anim` → `.ab`

```powershell
build/Release/anim_converter.exe --input Walk.anim --output build/ab/Walk.ab `
  --skeleton build/anim/character.skeleton.json

build/Release/anim_converter.exe --batch Assets/Animations --out-dir build/ab `
  --skeleton build/anim/character.skeleton.json

# 从 .fbx.meta 生成 Avatar 草稿
build/Release/anim_converter.exe --fbx-meta Character.fbx.meta `
  --emit-avatar build/anim/character.avatar.json
```

Humanoid 肌肉空间的跨骨架播放/重定向还需要与源骨架匹配的 `HumanoidAvatar`。
普通 BoneLocal Clip 不需要 Avatar。

### 4.2 glTF/GLB → `.ab` + skeleton + manifest

```powershell
cmake -S . -B build_pack -DANIM_BUILD_ANIM_PACK=ON
cmake --build build_pack --config Release --target anim_pack anim_pack_demo

build_pack/tools/anim_pack/Release/anim_pack.exe `
  --input tests/fixtures/anim_pack/simple_rig.glb `
  --out-dir build_pack/anim_out `
  --manifest tests/fixtures/anim_pack/simple_rig_manifest.json

# 可选：事件 sidecar
build_pack/tools/anim_pack/Release/anim_pack.exe `
  --input tests/fixtures/anim_pack/simple_rig.glb `
  --out-dir build_pack/anim_out `
  --manifest tests/fixtures/anim_pack/simple_rig_manifest.json `
  --events tests/fixtures/anim_pack/simple_rig_events.json
```

`--manifest` 是 `anim_pack` 的必需参数。输出的 manifest 会引用生成的 skeleton 和全部 `.ab`。
完整 Blender 工作流见 [18-Blender资产管线与运行时补齐](18-Blender资产管线与运行时补齐.md)。

### 4.3 校验

```powershell
cmake --build build --config Release --target anim_validate
build/tools/anim_validate/Release/anim_validate.exe `
  --manifest build_pack/anim_out/simple_rig_manifest.json `
  --json build_pack/anim_out/validation-report.json --strict
```

退出码：正常 `0`，`--strict` 下存在 error 为 `1`，参数错误为 `2`。

## 5. bgfx 查看器

### 5.1 构建

```powershell
cmake -S . -B build -DANIM_BUILD_SAMPLES=ON `
      -DANIM_BGFX_ROOT=E:/Learn/bgfx `
      -DANIM_ASSIMP_ROOT=E:/Learn/assimp
cmake --build build --config Release --target bgfx_demo
```

可执行文件默认在 `build/samples/bgfx_demo/Release/bgfx_demo.exe`。

### 5.2 单个 Clip

```powershell
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --clip build/ab/Walk.ab --frames 65 `
  --screenshot build/walk --screenshot-frame 50 --camera-yaw 25
```

`--screenshot` 写出 PPM（`<prefix>.ppm`）。截图需要固定 `--fixed-dt` 时，30 fps 使用
`0.0333333`，60 fps 使用 `0.0166667`。

### 5.3 manifest 多 Clip

```powershell
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest build_pack/anim_out/simple_rig_manifest.json `
  --frames 120
```

- `--clip-name Walk` 可重复，只加载指定 Clip。
- manifest 模式会校验 `skeletonFile` 与模型骨数；不一致时退出 `1`。
- Humanoid Clip 需要 `--avatar` 或模型 `.meta` 中的 HumanDescription；示例默认使用
  `tests/golden/DefaultHumanoid.source.avatar.json`。

### 5.4 headless 快照

```powershell
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --clip-name Walk `
  --headless --fixed-dt 0.0333333 --frames 60 `
  --snapshot-frame 30 --snapshot build/walk-frame30.json `
  --snapshot-history build/walk-history.json
```

- `--headless` 必须配合 `--snapshot` 或 `--snapshot-history`。
- `--snapshot-frame` 达到后导出并退出。
- 固定 dt/frame 时同一命令的 JSON 输出应逐字节稳定。
- `--snapshot-history` 使用 `Recorder`；事件名仍以 hash 存储，overlay/`--log-events` 会使用
  manifest 名称映射。

### 5.5 overlay、图、骨架线、事件

```powershell
# 文字 overlay + 事件日志（事件名优先显示 manifest 名称）
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --clip-name Walk `
  --debug-overlay --log-events --frames 120

# 输出一次图结构后退出；Debug tools 关闭时参数错误
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --graph

# 显示当前 pose 的骨架线（V 可运行时开关）
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --clip-name Walk --show-skeleton
```

截图示例：

```powershell
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --clip-name Walk `
  --debug-overlay --show-skeleton `
  --fixed-dt 0.0333333 --frames 20 `
  --screenshot build/skeleton --screenshot-frame 15
```

### 5.6 交互键

| 键 | 行为 |
|----|------|
| `Space` | 播放/暂停图 |
| `.` | 暂停时单步 |
| `R` | 当前 Clip 回到起点 |
| `Up/Down` | 切换 Clip |
| `Tab` | 切换当前层 |
| `D` / `E` | overlay / 事件日志开关 |
| `G` | dump 图结构 |
| `S` | 导出当前快照 |
| `V` | 骨架线开关 |
| `[` / `]` | 图速度 -/+ |
| `Esc` | 退出 |

### 5.7 D5 只读预览

```powershell
build/samples/bgfx_demo/Release/bgfx_demo.exe `
  --manifest anim_manifest.json --clip-name Idle --clip-name Walk `
  --preview-fade 1.0 --preview-fade-mode fixed-duration `
  --preview-start 0 --preview-speed 1.0 --preview-loop `
  --preview-switch-frame 20 --debug-overlay `
  --fixed-dt 0.0333333 --frames 40 `
  --screenshot build/crossfade --screenshot-frame 35
```

可用参数：

- `--preview-fade seconds`
- `--preview-fade-mode fixed-speed|fixed-duration|from-start|normalized-speed|normalized-duration|normalized-from-start`
- `--preview-start normalized`
- `--preview-speed value`
- `--preview-loop` / `--preview-no-loop`
- `--preview-switch-frame N`：在第 N 帧切到下一个 Clip，主要用于 headless/截图验收

预览键：`F` fade、`M` fade mode、`T` start、`-`/`=` 当前状态速度、`L` loop、`K` 恢复 manifest 默认值。
所有预览配置只在内存中修改，不写回 manifest/`.ab`；fade 结束后旧状态会被回收。

## 6. 运行时调试库

### 6.1 快照

```cpp
#include "anim/debug/Snapshot.h"

anim::debug::Snapshot snapshot;
anim::debug::captureInto(animator.playable(), snapshot);
const std::string json = anim::debug::toJson(snapshot);
```

`captureInto` 复用容量，适合每帧或固定频率刷新；需要单独构建时链接 `anim::debug`，
或打开 `ANIM_BUILD_DEBUG_TOOLS`（默认 ON）。

### 6.2 Recorder

```cpp
#include "anim/debug/Recorder.h"

anim::debug::Recorder recorder;
recorder.attach(animator.playable());

animator.update(dt);
recorder.recordFrame();

std::string error;
recorder.writeJsonFile("history.json", error);
```

Recorder 记录帧环和事件环；事件为 `Normal`/`End`，包含 state、frame、forward、归一化时间和
事件名 hash。它只读旁听，不改变播放顺序。

## 7. 接入自己的引擎

- 链接 `anim::anim`；不要把 bgfx/assimp 引入核心库。
- 导入期确定骨架顺序，`.ab` 的骨骼索引必须与该顺序一致。
- 每帧 `update(dt)` 后上传 `palette()`；并行 Job 需要同步。
- `consumeRootMotion()` 只返回 delta，是否应用由角色控制器决定。
- 坐标系在导入期转换；不要每帧转换 Pose/Palette。
- `palette()` 是 glm 列主序；只有 bgfx/HLSL 示例需要转置。
- 需要 Humanoid 重定向时再引入 `HumanoidAvatar`，普通同骨架 Clip 不走肌肉空间。
- 需要 ECS 时可选 `ANIM_ENABLE_ENTT`，核心不依赖 EnTT。

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| `manifest skeleton bone count ... does not match model` | manifest 的 skeletonFile 与模型不是同一骨架/顺序 |
| `humanoid clip requires --meta ... or --avatar` | 补 `.fbx.meta` 的 HumanDescription 或传 `--avatar` |
| `clip name not found in manifest` | 检查 `--clip-name` 与 manifest `clips[].name` |
| `cannot load shaders` | 在构建目录运行，或显式传 `--shaders build/samples/bgfx_demo/Release/shaders` |
| `--headless` 参数错误 | 同时传 `--snapshot` 或 `--snapshot-history`，并设置 `--snapshot-frame` |
| `--graph` / overlay / 快照参数错误 | 当前构建关闭了 `ANIM_BUILD_DEBUG_TOOLS` |
| `--show-skeleton` 提示 cannot load debug shaders | 确认 `shaders/vs_debug.bin`/`fs_debug.bin` 存在，或用 `--shaders` 指向目录 |
| `--preview-switch-frame requires at least two clips` | 用两个 `--clip-name`，或去掉该验证参数 |
| Debug 版 bgfx 启动挂起 | 用 Release 运行示例 |
| 事件日志只有 hash | Clip/Transition 没有 manifest 名称映射；这是只读 event 的预期回退 |
